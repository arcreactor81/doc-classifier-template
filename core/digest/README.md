# Digest policy and integration

`buildDigest(input, { budget, vocabulary, policy, codec })` returns the exact serialized named-field state, its token count, notes, and a separate selection log. `DIGEST_POLICY_VERSION` is `named-fields-json-v1`. A project pack must explicitly record this version, tokenizer ID, acceptedBy and acceptedAt. There is no runtime tokenizer fallback. The injected codec must use the selected tokenizer and return the longest literal prefix accepted by the whole-state budget predicate. Character counting in tests is exclusively a test codec.

The policy counts **all JSON state**, including keys, separators, title, headings, table headers and selected section text. The audit selection log is not model state. Title and outline text are retained even when repeated. A title uses metadata when supplied, otherwise first heading, otherwise first text block. Heading and table records remain complete, in position order. Body selection uses heading groups, prioritising structural vocabulary phrases matched as case-insensitive whole Unicode word sequences; all other headings follow in position order. Blocks without a heading follow these sections. No-outline documents use text blocks in position order. The first trimmed block ends selection; every subsequent omitted block remains in the log. Log lengths and positions use JavaScript UTF-16 units. The caller must send the returned serialized state unchanged and use the same named fields in vendor instructions.

The exact title/outline representation, unheaded-block placement, repeated title accounting, whole-state serialization budget, and truncation boundary are versioned generic policies chosen under the owner's authorization to choose and document configurable initial settings. They must be recorded in the Git-managed pack before a run. Structural vocabulary collision validation belongs to the project-pack loader.

`verifyRecoveredHeadings(text, candidates)` accepts only exact nonempty extracted-text lines. It does not trim, repair, deduplicate, or select among repeated lines. Each verified candidate contains every exact UTF-16 position. The integration layer must preserve the raw model response separately and explicitly resolve repeated-line placement before constructing recovered headings; this verifier never invents a position. Rejected candidates are returned for audit. Once recovery is used, integration must add `N_OUTLINE_RECOVERED` to document notes.
